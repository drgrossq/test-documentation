## О проекте

Репозиторий представляет собой учебный проект, выполненный в качестве портфолио. В рамках проекта составлена полная тестовая документация по тестированию веб-приложения **SauceDemo** — учебного интернет-магазина от компании Swag Labs, расположенного по адресу [www.saucedemo.com](https://www.saucedemo.com).

Документация охватывает весь цикл тестирования: от стратегии и планирования до оформления дефектов. Работа выполнена вручную, с применением техники чёрного ящика. Репозиторий демонстрирует навыки составления тест-плана, проектирования тест-кейсов, формирования чек-листов и оформления баг-репортов по стандартизованным шаблонам с классификацией Severity и Priority.

## Объект тестирования

**SauceDemo** — учебное веб-приложение компании Swag Labs, предназначенное для отработки навыков ручного и автоматизированного тестирования. Приложение имитирует работу классического интернет-магазина и реализует полный цикл пользовательского взаимодействия: авторизацию, просмотр каталога товаров, работу с корзиной и оформление заказа. Приложение доступно только по протоколу HTTPS, не требует установки дополнительного ПО и работает в любом современном браузере.

Тестирование охватывает пять ключевых функциональных модулей:

| # | Модуль | Описание |
|---|--------|----------|
| 1 | **Авторизация (Login)** | Форма входа, валидация учётных данных, обработка ошибок, выход из системы |
| 2 | **Каталог товаров (Inventory)** | Список товаров, сортировка по имени и цене, карточка товара |
| 3 | **Корзина (Cart)** | Добавление и удаление товаров, изменение количества, расчёт стоимости |
| 4 | **Оформление заказа (Checkout)** | Форма данных покупателя, обзор заказа, подтверждение, страница успеха |
| 5 | **Навигация (Menu)** | Боковое меню, переходы между страницами, сброс состояния приложения |

## Ключевые метрики

> **1** тест-план · **135** тест-кейсов · **143** чек-листа · **12** баг-репортов 

- **135 тест-кейсов** — детальные сценарии с предусловиями, шагами выполнения, ожидаемым результатом и постусловиями;
- **143 чек-листа** — стандартизованные проверки для функционального, UI/UX, адаптивного и кроссбраузерного тестирования;
- **12 баг-репортов** — оформленные отчёты о дефектах со скриншотами, шагами воспроизведения, классификацией Severity (Blocker → Trivial) и Priority (P1–P4);

## Виды тестирования

**Функциональное тестирование** — основной вид, проверяющий соответствие фактического поведения приложения заявленным требованиям. Покрытие включает позитивные и негативные сценарии, валидацию полей ввода, обработку ошибок и граничные значения для каждого модуля. Приоритизация выполняется на основе Risk-Based Testing (RBT): оценка по вероятности возникновения и воздействию.

**UI/UX тестирование** — проверка визуальной корректности интерфейса: вёрстки страниц, шрифтов, цветов, иконок, выравнивания и отступов, отсутствия наложений и перекрытий элементов, читабельности текста. Включает адаптивную проверку на мобильных и планшетных разрешениях и кроссбраузерное тестирование.

**Регрессионное тестирование** — двухуровневая стратегия: smoke-тестирование критических функций перед каждым раундом и расширенная регрессия полного набора приоритетных кейсов перед формированием итогового отчёта. По результатам формируется отчёт о покрытии и статусе выполнения.

## Как читать репозиторий

Для последовательного ознакомления с проектом рекомендуется следующий порядок:

1. **[`Test_Plan.md`](./Test_Plan.md)** — начать с стратегии: цели, объём тестирования, виды, окружение, критерии приёмки и классификация дефектов. Документ задаёт контекст для всех последующих артефактов.
2. **[`Checklists/`](./Checklists/)** — обзор проверок по каждому модулю. Чек-листы дают быстрое представление о покрытии функциональности и адаптивности без необходимости читать детальные шаги.
3. **[`Test_Cases/`](./Test_Cases/)** — детальные сценарии с шагами и ожидаемыми результатами. Здесь видна глубина проработки позитивных и негативных сценариев, валидации полей и граничных значений.
4. **[`Bug_Reports/`](./Bug_Reports/)** — оформленные дефекты со скриншотами, шагами воспроизведения и классификацией Severity/Priority. Каждая подпапка содержит каталог `assets/` с вложениями.
